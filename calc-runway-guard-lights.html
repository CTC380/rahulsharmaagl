Calculator #11 · Safety-Critical

Runway Guard Lights (RGL)

Applicability engine, elevated/in-pavement configuration, taxiway-centreline & intersection-angle geometry with local-to-airport coordinate transform, Stop Bar relationship, flashing/electrical test framework, and BOQ output.

About this calculator

RGL is a runway-intersection conspicuity warning system, not a holding/clearance control system — that is Calculator #10's Stop Bar. This calculator never reports RGL quantity as equal to Stop Bar quantity, never auto-installs RGL at every intersection, and never lets a user freely override a standard-defined parameter without flagging it as a project deviation.

Taxiway Centreline Reference & Intersection Geometry

Rule note

PCL is the taxiway centreline / runway intersection reference point. Every RGL position is calculated relative to PCL, then transformed into airport coordinates using the taxiway heading — the RGL line is set out square to the taxiway centreline; the intersection angle is recorded only. A simplified, clearly-documented model, since the exact position/spacing database is project/standard-verified.

Rule note

Taxiway/runway intersections are not always 90°. θ is recorded for the schedule and report only: the RGL line is always set out square (90°) to the taxiway centreline, so it does not rotate with θ.

Rule note

Separate from the left/right symmetry tolerance. If left blank the symmetry tolerance T is used and the result is shown as provisional.

Method & Reference

How This Calculator Works

Standard → Applicability → Configuration → Position Engine → Stop Bar/Holding Relationship → Quantity → Compliance. RGL is never auto-installed, never assumed equal to Stop Bar quantity, and never given an arbitrary user-defined flash characteristic.

Stop Bar ≠ RGL

Stop Bar = controlled clearance/holding indication. Runway Guard Light = conspicuity warning of a runway intersection. They are functionally distinct, standard-database-distinct, and quantity-distinct — this calculator never derives one from the other.

Applicability before quantity

The first calculation is applicability (Required / Recommended / Not Required / Project-Specific / Engineering Review), not quantity. RGL is not automatically installed at every runway intersection — applicability depends on the governing standard and the airport's operating configuration, entered explicitly rather than assumed.

Elevated vs. in-pavement quantity

Elevated: Q = 2 housings × sources/housing     In-Pavement: N = ⌈ L / Sdesign ⌉ spaces → Sactual = L / N, lights = N + 1

Worked example (in-pavement, illustrative): L = 23 m, Sdesign = 3 m → N = 8 spaces, Sactual = 2.875 m, 9 lights (one at each end of the coverage length). The in-pavement quantity is never assumed equal to the elevated quantity — each configuration loads its own geometry.

Left/right symmetry

ΔD = |DL − DR|

Checked against the symmetry tolerance T. A configuration is reported symmetrical or asymmetrical based on this measured difference, not assumed from the configuration type alone.

Local → airport coordinate transform

transverse° = heading° + 90°     Xairport = X0 + xlocal·cos(transverse)     Yairport = Y0 + xlocal·sin(transverse)

PCL is the taxiway centreline/runway intersection reference. Every RGL position is generated relative to PCL in local coordinates, then transformed using the taxiway heading. The RGL line is always set out square (90°) to the taxiway centreline; the intersection angle θ is recorded for reference only. A simplified, explicitly-documented model (not a published standard table); local X is positive to the left when facing along the heading.

Flashing frequency test

D = Fobserved − Frequired     %Deviation = (|D| / Frequired) × 100

The allowable deviation tolerance is entered from the applicable standard rather than hard-coded — left blank, the deviation is reported without a PASS/FAIL verdict.

One elevated housing may contain multiple optical sources. This calculator reports housing quantity, optical/light-source quantity, and physical assembly quantity separately, preventing procurement confusion between "2 housings" and "2 lit surfaces" when a housing contains more than one source.

What this calculator does not do

It does not maintain the exact ICAO or FAA RGL configuration/applicability tables, does not resolve the exact position/spacing database, and its intersection-angle coordinate transform is a documented simplification rather than a published standard formula. Applicability engine, configuration-specific geometry, symmetry, Stop Bar relationship, and quantity distinctions are fully calculated; exact figure-level configuration must be confirmed against the approved layout.

FAQ

Runway Guard Lights Calculator: Frequently Asked Questions

Quick answers on RGL applicability, configuration, quantity and the inspection checks.

What does the Runway Guard Lights Calculator do?

It works through runway guard light (RGL) applicability, configuration, position and quantity in a fixed order: standard, applicability, configuration, position engine, stop bar and holding position relationship, quantity and compliance. It also records an existing installation's measured fixtures, flashing frequency and electrical test values, and produces a coordinate schedule, BOQ and PDF report.

Is a runway guard light required at every runway intersection?

No. RGL is not automatically installed at every runway intersection. Applicability depends on the governing standard and the airport's operating configuration, so the first calculation is applicability, not quantity. You select the outcome as Required, Recommended, Not Required, Project-Specific or Engineering Review, per the applicable document.

What is the difference between a runway guard light and a stop bar?

A stop bar is a controlled clearance and holding indication. A runway guard light is a conspicuity warning of a runway intersection. They are functionally distinct, have separate standard databases and separate quantities, so the calculator never derives one from the other and never reports RGL quantity as equal to stop bar quantity.

How is the RGL quantity calculated for elevated and in-pavement configurations?

An elevated configuration has Q = 2 housings × optical sources per housing. An in-pavement configuration uses N = ⌈L ÷ Sdesign⌉ equal spaces, so N + 1 lights, with Sactual = L ÷ N. For example, L = 23 m and Sdesign = 3 m give N = 8 spaces, Sactual = 2.875 m and 9 lights. The in-pavement quantity is never assumed equal to the elevated quantity, and a project-specific configuration takes the total unit count you enter.

Why does the calculator report housings, optical sources and assemblies separately?

One elevated housing may contain more than one optical source. Reporting housing quantity, optical-source quantity and physical-assembly quantity separately avoids procurement confusion between 2 housings and 2 lit surfaces.

Does the calculator hard-code the ICAO or FAA RGL quantities and spacing?

No. The exact ICAO, FAA and DGCA configuration, applicability and position or spacing database is not incorporated. Those values are entered from the applicable document, and if the spacing limit is left blank the check is skipped. The flash characteristic also comes from the standard and RGL type, and arbitrary user-defined flash timing is not accepted into the compliance calculation.

How does the calculator handle angled intersections?

Every RGL position is generated relative to PCL, the taxiway centreline and runway intersection reference point, in local coordinates. It is then transformed to airport coordinates using the taxiway heading, with the RGL line set out square (90°) to the taxiway centreline. The intersection angle θ is recorded for reference but does not rotate the RGL line, so the model stays valid for angled intersections. This is a simplified and documented model.

What checks does it make on an existing RGL installation?

It checks left and right housing symmetry as ΔD = |DL − DR| against the symmetry tolerance, the distance from the RGL to the holding position against the allowable value and tolerance, and duplicate positions. It also compares the observed flashing frequency with the required value as a percentage deviation, and records supply voltage, current, insulation resistance, earth continuity, circuit and control panel IDs and operating status. It also compares the measured fixture count and type with the design. A Fault operating status fails the compliance matrix, but no pass or fail limit is applied to the electrical values. The allowable deviation is entered from the applicable standard, and if it is left blank no PASS or FAIL verdict is given.
