The improvement and knowledge-transfer division of the AGL Failure Database. Divisions 01–20 establish what failed, Division 21 establishes why, Division 22 establishes how serious it was, and Division 23 establishes the reliability trend it creates. CAPA-01 Immediate Corrective Action
Definition

The action taken immediately after failure detection to control the situation, restore required functionality or reduce immediate risk.

Examples
  • Isolating failed equipment
  • Replacing a failed fixture
  • Restoring a circuit
  • Temporary component replacement
  • Removing damaged equipment from service
  • Making the affected area safe
Required Record
  • Failure ID
  • Action taken
  • Date/time
  • Person/team
  • Equipment affected
  • Operational status after action
  • Temporary/permanent status
Important

Immediate corrective action does not necessarily eliminate the root cause.

CAPA-02 Temporary Corrective Action
Definition

A short-term action used to restore or maintain functionality until a permanent solution can be implemented.

Examples
  • Temporary replacement
  • Temporary bypass where technically and operationally permitted
  • Temporary equipment substitution
  • Temporary sealing/protection
  • Temporary operational arrangement
Database Requirement
  • Temporary-action description
  • Reason
  • Risk/limitation
  • Responsible person
  • Permanent-action requirement
  • Target completion date
  • Status
Critical Principle

Temporary restoration must not automatically be treated as failure closure.

CAPA-03 Permanent Corrective Action
Definition

The action that addresses the established failure mechanism/root cause and restores the equipment/system to the required condition.

Examples
  • Permanent component replacement
  • Design correction
  • Cable replacement
  • Connector replacement
  • Corrective wiring
  • Permanent sealing improvement
  • Equipment modification
Link

Division 21 Root Cause → Division 24 Permanent Corrective Action. The permanent action should be demonstrably related to the identified cause.

CAPA-08 Failure Closure
Definition

Formal closure of the failure after corrective action and required verification have been completed.

Recommended Closure Conditions

A failure should normally not be closed until:

  • Corrective action completed
  • Required testing completed
  • Equipment restored
  • Root cause addressed or appropriately dispositioned
  • Required documentation updated
  • Operational status confirmed
  • Corrective-action effectiveness established where required

B. Corrective Action vs. Preventive Action

This distinction should be maintained carefully.

Corrective Action

Fix the existing failure/problem.

Failed connector → replace connector → test circuit → restore service.

Preventive Action

Prevent the same or similar failure from recurring.

Repeated connector failures → identify moisture/sealing problem → revise installation/sealing procedure → modify inspection → train personnel → monitor recurrence.

A repair is not automatically a preventive action.

C. Effectiveness Verification

One of the most important controls in Division 24. After corrective/preventive action, ask:

  • Was the action implemented? Yes / No
  • Was the root cause addressed? Yes / No / Partially
  • Was the equipment tested? Yes / No
  • Did the failure recur? Yes / No
  • Did the failure rate improve? Yes / No / Not yet enough data
  • Did the same failure occur elsewhere? Yes / No
  • Is further action required? Yes / No

Frequently Asked Questions

Quick answers about corrective action, preventive action and lessons learned, as covered in Division 24 of the AGL Failure Database.

Q1What is Division 24 — Corrective Action, Preventive Action & Lessons Learned in the AGL Failure Database?

Division 24 is the closed-loop improvement system of the database. It contains 27 published topics (CAPA-01 to CAPA-27) covering corrective action, preventive action and lessons learned.

Q2How are the 27 CAPA topics grouped?

They fall into three groups: Corrective Action (8 topics), Preventive Action (10) and Lessons Learned (9).

Q3What corrective actions does Division 24 cover?

Immediate, temporary and permanent corrective action, component replacement, equipment repair, system restoration, retesting and failure closure.

Q4What preventive actions and lessons does Division 24 cover?

Preventive actions include preventive-maintenance and inspection-frequency modification, design modification, installation, component, training, SOP and testing improvement, environmental protection improvement and spare-parts strategy improvement. Lessons cover failure, installation, testing, maintenance, design, manufacturing, reliability and safety lessons, plus future-project recommendations.

Q5What is the difference between corrective action and preventive action?

Corrective action fixes the existing failure, for example replacing a failed connector, testing the circuit and restoring service. Preventive action prevents the same or similar failure recurring, for example finding a moisture or sealing problem behind repeated connector failures, revising the installation procedure, modifying inspection, training personnel and monitoring recurrence. A repair is not automatically a preventive action.

Q6How is the effectiveness of an action verified?

After action is taken, the record asks whether it was implemented, whether the root cause was addressed, whether the equipment was tested, whether the failure recurred, whether the failure rate improved, whether the same failure occurred elsewhere and whether further action is required.

Q7When should a failure be closed?

A failure should not be closed merely because the equipment has been repaired. It should be closed only when the required corrective action has been verified, recurrence risk has been addressed and the knowledge gained has been captured for future maintenance, design, procurement, testing and projects.

Q8What is the CAPA master workflow?

The failure occurs, followed by immediate corrective action, temporary restoration if needed, RCA (Division 21), severity and criticality (Division 22) and reliability trend (Division 23). Permanent corrective action, retesting, system restoration and verification follow, then preventive action, lessons learned, SOP, design, training or product updates, future-project recommendations, recurrence monitoring and failure closure.
