AGL Technology Comparison

STANDALONE SYSTEM VS INTEGRATED A-SMGCS

A standalone AGL system operates and controls airfield lighting independently, while an A-SMGCS-integrated system exchanges status, control and/or operational information with the Advanced Surface Movement Guidance and Control System (A-SMGCS). One is self-contained; the other is a defined system interface — and integration should be treated as engineering, not just "remote control of lights."

04 · Context

What Is A-SMGCS?

A-SMGCS is an airport surface-management system intended to support the safe and efficient movement of aircraft and vehicles on the aerodrome surface. It can involve surveillance, routing, guidance, control, situational awareness, and traffic management. AGL can become one of the systems that provides visual guidance information to support surface movement.

05 · Why Integrate

Why Integrate AGL with A-SMGCS?

The main reason is to make lighting behaviour more closely coordinated with actual surface operations.

Aircraft requires taxi route
          ↓
A-SMGCS determines route
          ↓
Relevant taxiway guidance
          ↓
AGL system receives command
          ↓
Appropriate lights/signs operate

This can provide a more dynamic lighting environment than a purely standalone system.

12 · Critical Engineering Issue

Fail-Safe Consideration

Suppose communication between A-SMGCS and AGL is lost. The system must have a defined behaviour.

A-SMGCS
   X
   X  Communication lost
   X
AGL
   ↓
Defined fallback state

Possible design principles include:

  • Maintain current safe state
  • Return to predefined configuration
  • Transfer to local control
  • Generate alarm
  • Prevent unauthorized automatic commands

The exact response must be specified and validated for the particular airport system.

13 · Design Principle

Local Control Should Remain Important

An integrated A-SMGCS interface should not mean "if the network fails, the airport loses all lighting control." A robust architecture normally defines operational priorities and fallback modes.

A-SMGCS
   ↓
Automatic / integrated control
        ↕
AGL Control System
        ↓
Local / manual control
        ↓
AGL equipment

The actual control hierarchy must be defined in the system requirements.

14 · Interface Types

The Interface Is Not a Single Fixed Protocol

The interface can involve digital communication, Ethernet/IP, serial communication, hardwired I/O, PLC/RTU, middleware/gateway, or proprietary interfaces.

"A-SMGCS interface" does not define a specific communication protocol by itself. The project specification needs to define the actual interface.

17 · Cybersecurity

Integration Widens the Attack Surface

A standalone system has fewer external digital connections. An integrated A-SMGCS system introduces additional interfaces.

A-SMGCS
   ↕
Network
   ↕

The integrated system requires attention to:

  • Network security and access control
  • Authentication and segmentation
  • Configuration management and logging
  • Remote-access controls
  • Failure/recovery procedures

The exact cybersecurity requirements depend on the airport's IT/OT architecture and applicable policies.

21 · Engineering Verdict

Standalone System vs Integrated A-SMGCS Interface

Engineering Verdict

A standalone AGL system operates independently, whereas an A-SMGCS-integrated AGL system exchanges defined control, status and operational information with the airport's surface-movement management system.

The key engineering point is that A-SMGCS integration should be treated as a defined system interface — not simply as "remote control of lights." The interface requirements should explicitly define data exchanged, commands, priorities, interlocks, failure behaviour, communication loss, cybersecurity, and FAT/SAT acceptance criteria.

StandaloneAGL operation independent; lighting control belongs to the AGL system.
IntegratedAGL ↔ A-SMGCS status/command exchange; higher complexity and cybersecurity importance.

The exact architecture, protocol, and fallback behaviour must always come from the airport's approved system design and interface specification — not a generic diagram.

22 · FAQ

Frequently Asked Questions

What is the fundamental difference between a standalone AGL system and an A-SMGCS-integrated system?

A standalone system operates and controls airfield lighting independently. An integrated system additionally exchanges status, control and/or operational information with A-SMGCS through a defined interface.

Does A-SMGCS control individual light fixtures directly?

Usually not. A-SMGCS generally communicates at a system/control level with the AGL control system, which then manages the detailed lighting equipment such as CCRs and circuits.

What happens if communication between A-SMGCS and AGL is lost?

The system must have a defined fallback behaviour — such as maintaining the current safe state, returning to a predefined configuration, transferring to local control, or raising an alarm. The exact response must be specified and validated for the particular airport system.

Does "A-SMGCS interface" mean a specific communication protocol?

No. The interface can be implemented through digital communication, Ethernet/IP, serial communication, hardwired I/O, PLC/RTU, middleware/gateway, or proprietary means. The project specification defines the actual interface.

Does integration increase cybersecurity requirements?

Yes. An integrated system introduces additional network interfaces and therefore requires attention to network security, access control, authentication, segmentation, configuration management, logging, and remote-access controls.

Should every AGL system be integrated with A-SMGCS?

Not necessarily. Integration adds architectural, network and cybersecurity complexity, plus more extensive FAT/SAT. It should be justified by actual operational requirements rather than pursued simply because it's technologically possible.

23 · Standards & Reference Basis

Governing Documents

For an actual project, always verify the current edition of the applicable documents and the approved interface specification.

ICAO Doc 9830 (A-SMGCS Manual)

ICAO guidance on Advanced Surface Movement Guidance and Control System functions, architecture and implementation levels.

ICAO Annex 14 / FAA AC 150/5340-30

Underlying AGL design and installation requirements that any A-SMGCS interface must still comply with at the lighting-system level.

Applicable IT/OT Cybersecurity Policy

Airport or national cybersecurity requirements governing network segmentation, access control and remote access for integrated systems.

Final Engineering Note

Do not assume a generic architecture diagram defines the actual interface. The data exchanged, commands, priorities, interlocks, and fail-safe behaviour must always be defined in the approved project interface specification.

A standalone system and an A-SMGCS-integrated system are not simply "basic vs advanced" — they represent different architectural decisions with different testing, cybersecurity and fail-safe obligations.
