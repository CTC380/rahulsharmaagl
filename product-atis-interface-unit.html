Product Overview

ATIS Interface Unit

What It Is

The ATIS Interface Unit provides an interface between airport meteorological and operational data systems and the airport’s Automatic Terminal Information Service (ATIS) environment.

It collects, formats, transfers or distributes approved data from connected airport systems so relevant information can be made available to the ATIS application or associated aerodrome information system.

What We Provide

Depending on the system architecture, the interface can support information from weather sensors, RVR systems, airport operational databases, runway status systems and other approved data sources.

Precision AGL Solutions provides ATIS interface configurations for new airport installations, system upgrades, and integration of existing meteorological equipment with modern digital airport information networks.

Data Content & Units

Set Units and References Before the Data Goes Live

Configure and Test

  • Wind direction reference: ATIS and local routine reports use degrees magnetic, while METAR uses true, so set the reference in the configuration
  • Pressure units (hPa or inHg) and the QNH or QFE value required
  • RVR and visibility reported only under the conditions the authority sets, with units in metres
  • Averaging periods: local routine and ATIS reports use a 2-minute mean wind, METAR a 10-minute mean, so map each output to the correct source value (confirm against your Annex 3 edition)
  • Time stamp and data age, so stale readings are flagged rather than passed on
  • A failed sensor should show as missing or invalid, never as zero

Operational Responsibility

The interface moves and formats data. The content of the broadcast message, and the decision to release it, stay with the air traffic services and the meteorological provider. Feed the ATIS, wind display and ATS displays from the same validated source so all show matching values.

FAQ

ATIS Interface Unit — Frequently Asked Questions

What is an ATIS interface unit?

An ATIS interface unit provides an interface between airport meteorological and operational data systems and the airport’s Automatic Terminal Information Service (ATIS) environment. It collects, formats, transfers or distributes approved data from connected airport systems so the information can be made available to the ATIS application or an associated aerodrome information system.

What data sources can it connect?

Depending on the architecture, it can receive data from AWOS, RVR systems and transmissometers, wind sensors, visibility sensors, present weather sensors, atmospheric pressure data such as QNH, weather processors, runway status systems, airport operational databases and other approved data sources. Visibility sensors report meteorological optical range, and RVR is a separate data source.

What does the unit do with the data?

Depending on the selected configuration, it performs data acquisition, validation, conversion, formatting, routing and communication. It can validate communication integrity, availability, validity and system status, format data for the receiving ATIS application, distribute it, and report communication failures, unavailable sources or equipment faults, depending on the system design.

Which communication interfaces are supported?

Possible interfaces are Ethernet and TCP/IP-based communication, serial communication (RS-232, RS-422 and RS-485) and other manufacturer-specific digital interfaces. The actual protocol and physical interface for each connected system should be confirmed before procurement, and for third-party systems the compatibility should be verified using the approved communication protocol, data format, message structure and update-rate requirements.

What units and references need to be configured before data goes live?

Configure and test the wind direction reference, because ATIS and local routine reports use degrees magnetic while METAR uses true. Also set the pressure units (hPa or inHg) and the QNH or QFE value required, RVR and visibility reporting conditions with units in metres, and the averaging periods, since local routine and ATIS reports use a 2-minute mean wind and METAR a 10-minute mean (confirm against your Annex 3 edition). Include a time stamp and data age so stale readings are flagged, and a failed sensor should show as missing or invalid, never as zero.

Who is responsible for the content of the ATIS message?

The interface moves and formats data. The content of the broadcast message, and the decision to release it, stay with the air traffic services and the meteorological provider. The ATIS, wind display and ATS displays should be fed from the same validated source so all show matching values.

What should be defined during system engineering?

Define the number of meteorological data sources, RVR inputs, network connections and serial ports, any redundant interfaces, the data update frequency, input and output data formats, alarm and status outputs, the maintenance interface and remote monitoring requirements. This prevents interface limitations from becoming a constraint during system integration.

What network and power points need attention?

For network-connected installations the unit may operate within the airport’s secured IT infrastructure, so the design should consider network topology, IP addressing, segmentation, communication ports, data routing, redundancy, access control, remote maintenance, cybersecurity and time synchronization, in coordination with the airport’s IT and communications teams. For power, consider input voltage, AC or DC supply, power consumption, UPS where required, overcurrent and surge protection, earthing, power redundancy and backup power, following the airport electrical design and the manufacturer’s requirements.

How is the unit commissioned?

Commissioning typically covers an equipment inspection, a power-up test, a communication test with the AWOS, RVR system, weather processor, ATIS application and airport network, and data validation to confirm information is received, validated, formatted and transferred correctly. Where permitted, simulate selected communication or input failures to verify the expected fault indication, and finish with an end-to-end test of the complete data path from the originating sensor or system through the interface unit to the ATIS application.

What are the common faults and what should be checked?

If no data is received, check the source equipment, cabling and interface status. If ATIS data is unavailable, check the network connection and interface diagnostics. Incorrect data suggests a data-format or configuration mismatch, so verify the protocol and data mapping. Intermittent communication suggests a network, cable or connector problem, a delayed update suggests a source or update-rate issue and a unit that does not start suggests a power supply or hardware fault. Use the approved system documentation and manufacturer procedures.

Does an ATIS interface unit need redundancy?

ATIS is an operationally important airport information service, and provisions may include redundant power supplies, dual network connections, redundant interface units, backup data sources, failover communication paths, health monitoring and automatic fault indication. Redundancy requirements should be established from the airport operational concept and system availability requirements rather than assumed as a standard feature.

What information is needed to specify an ATIS interface unit, and which standards apply?

Confirm the ATIS and AWOS system manufacturers and models, the RVR interface, the number of data sources, inputs and outputs, communication protocols, data formats and update rates, network architecture, redundancy, power supply, enclosure, installation location, environmental and cybersecurity requirements, remote monitoring, documentation, FAT/SAT requirements and spare parts. References may include ICAO Annex 3, Annex 11, Annex 14 Vol. I and Annex 15, ICAO Doc 9837 and Doc 9328, India Meteorological Department requirements, DGCA CARs and airport-specific ATIS specifications. Confirm the applicable edition during engineering and procurement.
