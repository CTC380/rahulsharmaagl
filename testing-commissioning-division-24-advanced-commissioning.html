Division 24 · ADV · LED, Smart & Networked AGL Technologies

Advanced Commissioning

Modern AGL is no longer just lamps and cable — LED fixtures, smart controllers, remote monitoring platforms, networked equipment and airport-connected systems all carry sensing, communication, control, diagnostic and data functions that conventional electrical/functional commissioning does not exercise. Division 24 verifies the complete advanced-technology layer: LED system and thermal performance, smart AGL validation, intelligent and remote monitoring, remote diagnostics, digital control, smart sensors, networked equipment, data communication, cybersecurity where applicable, user access, communication security, backup arrangements, automation, and emerging airport technology.

Fundamental Principle: advanced AGL systems shall not be considered commissioned merely because the physical equipment operates — their sensing, communication, control, diagnostics, data integrity, access control and intelligent functions shall also be verified where those functions are provided. Divisions 01–23 cover conventional pre-commissioning, electrical, functional and system-level commissioning; Division 24 is the dedicated advanced/technology-forward layer, not a duplicate of that scope.

Advanced Commissioning Failure Classification

Because a failure in a smart AGL asset can occur at several different levels, Division 24 classifies failures separately from conventional divisions.

ClassExamples
A — Physical FailureLED fixture failure, driver failure, sensor failure, cable failure
B — Electrical FailureIncorrect voltage, current abnormality, insulation failure, power-supply failure
C — Control FailureIncorrect command, incorrect intensity, switching failure, interlock failure
D — Communication FailureNetwork loss, device communication loss, incorrect data, delayed feedback
E — Monitoring FailureIncorrect status, missing alarm, false alarm, incorrect diagnostic
F — Cybersecurity/Access FailureUnauthorized access, incorrect user privilege, authentication failure, security-control failure — where applicable

Before Testing Begins

Two conditions should be established before advanced commissioning of any LED, smart or networked AGL asset begins.

Numerical & Threshold Limits Are Not Universal

  • LED thermal verification uses the manufacturer/project-defined limits, not an arbitrary universal temperature limit
  • Sensor measurement accuracy and alarm thresholds are project- and equipment-specific, taken from the applicable datasheet
  • Cybersecurity checks are performed against the airport/operator's approved cybersecurity requirements and project specifications — a generic checklist is not a substitute for the airport's actual requirements
  • Future technology evaluation is an evaluation activity, not necessarily an acceptance requirement for every project

Division Boundary

  • Divisions 01–23 cover pre-commissioning, core electrical equipment, fixture/functional commissioning, photometric verification, FAT/SAT, system integration, performance acceptance, troubleshooting, documentation and handover
  • Division 24 is the dedicated advanced/technology-forward layer for LED, smart, networked and airport-connected AGL systems — it does not duplicate conventional commissioning already covered elsewhere
  • A command is never accepted as successful merely because it was sent — field response and feedback must confirm correct status
  • No advanced AGL asset is released until every applicable item in this division is closed, in addition to its conventional commissioning divisions

A

LED System Verification

3 topics
TC-ADV-001LED AGL System Verification
Verification Checks
  • Verify LED fixture identification, rating, and LED module type
  • Verify driver identification, input supply, operating current and operating voltage
  • Verify secondary connection and connector condition
  • Verify fixture operation, intensity settings and colour
  • Verify optical performance and thermal condition
  • Verify control compatibility with the associated CCR/controller
  • Record manufacturer, model, serial number, LED module information and driver information
  • Record test results and acceptance status
Acceptance / Record

Acceptance Criteria: fixture identity, rating, driver, and installed configuration match the approved design, and all documented fields are recorded before performance testing begins.

TC-ADV-002LED Fixture Performance Verification
Verification Checks
  • Test/verify light output, intensity and beam distribution
  • Test/verify colour and switching response
  • Test/verify intensity-step response and operating stability
  • Test/verify optical condition and driver operation
  • Compare specified performance against measured performance
Acceptance / Record

Acceptance Criteria: measured light output, intensity, beam distribution and colour meet the specified performance, and switching/intensity-step response and operating stability are confirmed correct.

TC-ADV-003LED Thermal-Performance Verification
Verification Checks
  • Verify fixture thermal condition and heat dissipation
  • Verify driver thermal condition and thermal protection
  • Check for abnormal temperature indications
  • Verify ventilation/heat-sink condition where applicable
  • Where monitoring is available, record temperature measurement, sensor value, alarm threshold, alarm response and protective response
Hold Point

Hold Point: thermal verification uses the manufacturer/project-defined limits rather than an arbitrary universal temperature limit.

B

Smart AGL & Intelligent Monitoring

2 topics
TC-ADV-004Smart AGL System Validation
Verification Checks
  • Verify smart equipment identification and equipment status
  • Verify communication, monitoring and control functions
  • Verify diagnostics and alarm generation
  • Verify data transmission, event recording and failure reporting
  • Verify each interface in the validation chain: Field Equipment → Sensor/Controller → Network → Monitoring Platform → Operator Interface
Acceptance / Record

Acceptance Criteria: each interface in the field equipment → sensor/controller → network → monitoring platform → operator interface chain is individually verified before the smart system is accepted.

TC-ADV-005Intelligent Monitoring Verification
Verification Checks
  • Verify equipment ON/OFF status, fault status and alarm status
  • Verify current/voltage data where provided
  • Verify equipment health status and communication status
  • Verify sensor status and diagnostic information
  • Create known field conditions where practical and verify the monitoring system reports the correct condition
Acceptance / Record

Acceptance Criteria: monitoring system output matches the actual field condition for every tested condition.

C

Remote Monitoring & Diagnostics

2 topics
TC-ADV-006Remote Monitoring Validation
Verification Checks
  • Test equipment status, circuit status and CCR status
  • Test alarm status and communication status
  • Test remote indications, event updates and monitoring response
  • Verify that the actual field condition equals the displayed remote condition
Hold Point

Hold Point: any discrepancy between the actual field condition and the displayed remote condition is investigated and documented before acceptance.

TC-ADV-007Remote Diagnostics Verification
Verification Checks
  • Verify fault identification, fault location and equipment health
  • Verify diagnostic codes, alarm details and historical information
  • Verify event records and maintenance information
  • Introduce or simulate applicable fault conditions
  • Verify the diagnostic system detects the condition, identifies the affected equipment, generates the appropriate indication, records the event, and clears/reports recovery correctly
Acceptance / Record

Acceptance Criteria: the diagnostic system correctly detects, identifies, indicates, records and reports recovery for every simulated fault condition.

D

Digital Control & Smart Sensors

2 topics
TC-ADV-008Digital Control Validation
Verification Checks
  • Verify digital commands and ON/OFF control
  • Verify intensity commands and circuit switching
  • Verify equipment selection and local/remote control
  • Verify command confirmation and feedback indication
  • Verify the chain: Command → Field Response → Feedback → Correct Status
Hold Point

Hold Point: a command is not accepted as successful merely because it was sent — field response and feedback must confirm correct status.

TC-ADV-009Smart Sensor Verification
Verification Checks
  • Verify sensor identification, installation and wiring
  • Verify power supply and communication
  • Verify measurement and accuracy as specified
  • Verify alarm threshold, status indication and failure indication
  • Applicable to current, voltage, temperature, equipment-status, environmental, door/status and other project-specific sensors
Acceptance / Record

Acceptance Criteria: each sensor's measurement accuracy, alarm threshold and status/failure indication are verified as specified.

E

Network & Data Communication

2 topics
TC-ADV-010Networked AGL Equipment Testing
Verification Checks
  • Verify equipment addressing and network connection
  • Verify communication status, data exchange and device identification
  • Verify status feedback, command communication and alarm communication
  • Verify network redundancy where applicable
  • Test normal communication, communication interruption, communication restoration, device restart and network recovery
Acceptance / Record

Acceptance Criteria: equipment correctly rejoins the network and resumes correct communication after interruption, device restart, or network recovery testing.

TC-ADV-011Data Communication Validation
Verification Checks
  • Verify data transmission, data reception and data integrity
  • Verify device status, alarm messages and command messages
  • Verify feedback messages, event messages and time/date information where applicable
  • Verify each stage: AGL Equipment → Controller → Network → Server/SCADA/ALCMS → HMI
Acceptance / Record

Acceptance Criteria: data integrity is confirmed at every applicable stage from field equipment through to the HMI.

F

Cybersecurity & Access Control

3 topics
TC-ADV-012Cybersecurity Checks Where Applicable
Verification Checks
  • Review network segregation and access control where applicable
  • Review user authentication, password controls and account management
  • Review remote-access controls and communication security
  • Review system hardening and software/firmware control
  • Review backup arrangements, logging and security-event recording
Hold Point

Hold Point: this is performed against the airport/operator's approved cybersecurity requirements and project specifications — a generic cybersecurity checklist is not a substitute for the airport's actual cybersecurity requirements.

TC-ADV-013User-Access Verification
Verification Checks
  • Verify user accounts, user roles and access levels
  • Verify administrator access, operator access and maintenance access
  • Verify read-only access where applicable
  • Verify disabled/removed accounts
  • Verify password requirements and authentication mechanisms
Acceptance / Record

Acceptance Criteria: each user account holds only the access level necessary for its assigned role, and disabled/removed accounts are confirmed closed.

TC-ADV-014Communication-Security Verification
Verification Checks
  • Verify authorized communication paths and network segmentation where applicable
  • Verify secure communication mechanisms and access restrictions
  • Verify remote-access restrictions and device authentication
  • Verify communication monitoring and unauthorized-access indication
  • Record security requirement, verification method, result, evidence and acceptance status
Acceptance / Record

Acceptance Criteria: authorized communication paths, segmentation and device authentication are verified, with security requirement, method, result and evidence recorded for each.

G

Backup, Automation & Future Technology

3 topics
TC-ADV-015System Backup Verification
Verification Checks
  • Verify backup exists for ALCMS configuration, PLC program, HMI configuration, CCR configuration, and system parameters
  • Verify backup exists for database, network configuration, device configuration, engineering files, and user/configuration settings
  • Verify the backup is identifiable and the backup date is recorded
  • Verify backup location is controlled and a restoration process is defined
  • Test restoration where required: Backup Created → Backup Verified → Restoration Tested Where Required
Acceptance / Record

Acceptance Criteria: Backup Created → Backup Verified → Restoration Tested Where Required is confirmed complete for every applicable system.

TC-ADV-016Future Airport Technology Evaluation
Evaluation Criteria
  • Assess technical feasibility, operational benefit and reliability
  • Assess maintainability, integration capability and cybersecurity
  • Assess lifecycle cost, training requirements and airport compatibility
  • May cover intelligent AGL monitoring, predictive maintenance, remote diagnostics, digital asset management, sensor-based condition monitoring, advanced ALCMS, automated fault detection, networked LED systems, digital maintenance records, automated inspection technologies, data analytics and AI-assisted maintenance where applicable
Acceptance / Record

Acceptance Criteria: this is recorded as an evaluation activity — not treated as a mandatory acceptance requirement unless the project specification requires it.

TC-ADV-017Advanced Automation Testing
Verification Checks
  • Verify automatic fault detection, automatic alarm generation and automatic status reporting
  • Verify automatic switching and automated intensity control
  • Verify automated diagnostics, automated recovery and condition-based monitoring
  • Establish normal operating condition, then initiate/simulate the applicable condition
  • Verify automation response, alarm, equipment response, operator indication, event logging and recovery, then record the result
Acceptance / Record

Acceptance Criteria: automation response, alarm, equipment response, operator indication, event logging and recovery are each individually verified for every tested automated function.

Five-Layer Acceptance Model

Advanced systems are evaluated across five layers before Division 24 is closed for a given asset — every layer has to hold.

1
Physical

Is the equipment correctly installed?

2
Electrical

Does the equipment operate electrically as specified?

3
Control

Does the equipment respond correctly to commands?

4
Communication

Does information move correctly between systems?

5
Intelligence

Does the monitoring/diagnostic/automation function correctly interpret and respond to the condition?
