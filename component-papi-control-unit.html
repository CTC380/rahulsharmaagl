PAPI Control Unit

The electronic brain of the PAPI system – managing intensity selection, lamp/LED monitoring, fault detection, and communication with the ALCMS. This unit ensures that the PAPI provides the correct brightness for day, twilight, and night operations, and alerts maintenance crews to any failures or degradations.

Overview

What Is It?

The PAPI Control Unit is an electronic device that manages the operation of a PAPI (Precision Approach Path Indicator) system. It is typically installed in the airfield electrical equipment room, near the Constant Current Regulator (CCR), or integrated with the CCR itself. The control unit performs several critical functions:

  • Intensity Selection: It receives brightness commands (typically from the ALCMS or a manual control panel) and translates them into appropriate current or PWM signals for the PAPI light units, adjusting intensity for day, twilight, and night operations.
  • Monitoring: It continuously monitors the electrical status of each PAPI unit, detecting lamp/LED failures, open circuits, or current deviations that could indicate a problem.
  • Fault Detection & Alarm: When a fault is detected, the control unit triggers an alarm (local and/or remote) to alert maintenance personnel. It logs fault events for later analysis.
  • Communication: It interfaces with the Airfield Lighting Control and Monitoring System (ALCMS) via serial, Ethernet, or other protocols, providing status data and receiving control commands.
  • Diagnostics: Advanced units perform self‑tests and provide diagnostic information to assist troubleshooting and reduce downtime.

The control unit is essential for maintaining the operational integrity of the PAPI system, ensuring that the visual glide slope indication remains reliable and that any failures are quickly identified and rectified.

Purpose

Purpose & Function

The control unit's purpose is to make four separately powered light units behave as one coherent instrument rather than four independent lights that happen to sit near each other. Coordinated intensity switching is the clearest example: when ambient light changes from day to twilight to night, all four units need to step down together, because if one lagged even briefly, the red/white balance a pilot is reading would be temporarily distorted for reasons that have nothing to do with the aircraft's actual glide path. Its monitoring and fault-detection role serves the same underlying goal from a different angle — a single failed unit within the array doesn't just mean "one light is out," it means the whole four-unit code the pilot depends on can no longer be trusted, so catching that failure immediately and raising an alarm is what prevents a degraded pattern from being flown as if it were a correct one.

Architecture

Key Functional Blocks

The PAPI control unit typically consists of several interconnected functional modules:

Processor & Logic

Microcontroller or PLC-based logic that executes control algorithms, monitors inputs, and drives outputs. Handles intensity switching, timing, and fault logic.

Intensity Control

Output circuits that send control signals to the CCR (or directly to LED drivers) to adjust the current or PWM duty cycle for each brightness step.

User Interface

Local display (LCD or LED indicators) and push‑buttons for manual control, status viewing, and configuration. May include a keypad for password‑protected settings.

Input/Output Interfaces

Digital and analog I/O for connecting to CCRs, sensors, and external alarms. Includes relay outputs for alarm signaling and status reporting.

Communication Module

Serial (RS‑232/485), Ethernet, or fibre‑optic interface for communication with the ALCMS, remote monitoring systems, or maintenance laptops.

Power Supply

Internal power supply (AC/DC) that powers the control unit electronics, often with redundant inputs or battery backup for critical monitoring.

Application

Where Is It Used?

The PAPI control unit is a standard component in every PAPI installation, regardless of scale or location:

  • Precision runways (CAT I, II, III) – integrated with the full ALCMS for automated intensity control and fault reporting.
  • Non‑precision runways – often paired with a standalone CCR or a simple manual control panel.
  • Heliports – controlling Helicopter PAPI systems with steeper angles.
  • Military airfields – with ruggedized units for tactical environments.
  • Portable or temporary PAPI – small, battery‑powered controllers for rapid deployment.
  • Retrofit upgrades – replacing older relay‑based controllers with modern microprocessor units to add monitoring and diagnostics.
Placement

Installation & Location

The control unit is installed in the airfield's electrical equipment room or CCR building, mounted on an equipment rack or panel close to the constant current regulator it interfaces with, since intensity and monitoring signals are exchanged over short, direct cabling wherever practicable. Where the unit is integrated with the CCR itself rather than housed separately, it is fitted within the CCR cabinet at manufacture, sharing the same enclosure, power supply, and equipment room environment as the regulator. Communication cabling to the ALCMS is run alongside other AGL control and monitoring cable routes back to the control room, kept identifiable and separate from unrelated circuits so a wiring fault doesn't cross-connect PAPI status into an unrelated system. Field wiring from the control unit out to each of the four PAPI light units is run in a common duct or cable route back to the array, with each unit's monitoring and intensity control leads kept individually identifiable so a fault reported by the control unit can be traced to the specific light it originates from.

Function

How Does It Work?

The PAPI control unit operates continuously to ensure the PAPI system is always ready for use:

  • Intensity Management: The unit receives a brightness command (e.g., from the tower or ALCMS) corresponding to day, twilight, or night. It then outputs a control signal to the CCR to adjust the series current to the appropriate level (e.g., 2.8A, 3.4A, 4.1A, 5.2A, 6.6A). For LED systems, it may send a PWM signal to the LED drivers.
  • Current Monitoring: It measures the actual current in the series circuit using a current transformer or shunt. This value is compared to the target; deviations beyond a tolerance trigger a fault alarm.
  • Unit Status Monitoring: Some advanced units monitor each PAPI unit individually (e.g., using a separate current sensor per unit) to detect lamp burnout or LED failure. This is typically done via a multiplexed measurement system.
  • Fault Detection Logic: The unit continuously evaluates the measured parameters against predefined thresholds. If a fault is detected (e.g., current too low, open circuit, short circuit), it activates a local alarm (buzzer, flashing LED) and sends a fault message to the ALCMS.
  • Communication: The unit exchanges data with the ALCMS using a standard protocol (Modbus, BACnet, or proprietary). The ALCMS can query the unit for status, retrieve fault logs, and send new intensity settings.
  • Local Override: In case of ALCMS failure, the unit often has a manual override switch or keypad to set the intensity locally.
  • Self‑Diagnostics: The unit runs periodic self‑tests (e.g., memory check, communication check) and reports its own health to the ALCMS.
Architecture

System Architecture & Control Logic

The PAPI control unit is the local control node that sits between the ALCMS and the four-unit array — every brightness command and every fault report passes through it. It receives an intensity command from the tower or ALCMS, translates that into a CCR current step or a PWM signal for LED drivers, and continuously measures the actual current (and, on advanced units, the status of each PAPI unit individually) to confirm the command was actually achieved.

This makes it functionally similar to the CCR-plus-ALCMS chain used for runway and taxiway loops, but scaled down and localised to one PAPI array, with an added resilience feature: because a PAPI is a critical glide-path aid, most control units include a manual override so intensity can still be set locally if the ALCMS communication link is lost, rather than leaving the array stranded at whatever level it was last commanded to.

ALCMS → PAPI Control Unit → CCR/LED Driver → 4-Unit Array (per-unit status feedback)

Construction

Physical Construction

The control unit is built as a rack-mount or wall-mount enclosure housing a power supply stage, a microcontroller or PLC-based logic board, relay or solid-state switching outputs, and a communications interface card, all on internal mounting rails or a chassis for serviceability. Front-panel indicators or a small display give local status at a glance, while a terminal block or connector panel on the rear or underside brings in mains power, field wiring to the PAPI units or CCR, and the communications link to the ALCMS. The enclosure itself is sized and rated for its installation location — a sealed, gasketed metal or polymer case for an outdoor equipment cabinet, or a simpler ventilated case where it sits inside an environmentally controlled equipment room — with internal components conformally coated or otherwise protected against humidity and dust ingress in either case.

Field Notes

Common Field Issues

Communication Loss

The control unit may lose communication with the ALCMS due to cable damage, connector corrosion, or network configuration errors. Regular checks of communication links and protocol settings are essential. Consider redundant communication paths for critical systems.

Current Sensor Drift

Current transformers or shunt resistors can drift over time, leading to inaccurate current readings and false fault alarms. Periodic calibration using a known‑good ammeter is recommended to maintain accuracy.

Relay Contact Welding

The output relays that switch CCR steps may weld closed due to high inrush currents or frequent switching. Use relays with appropriate ratings and consider solid‑state switches for heavy‑duty applications. Regular inspection and replacement of worn relays is necessary.

Power Supply Failure

Internal power supplies, especially in older units, can fail due to capacitor ageing or voltage spikes. Having a spare power supply module or an external UPS can prevent downtime.

Configuration Corruption

Settings such as brightness step levels, fault thresholds, and communication parameters can be lost due to battery failure or EEPROM corruption. Keep a backup of the configuration and ensure the unit has a reliable memory backup.

Faulty Wiring

Loose or corroded connections between the control unit and the CCR or PAPI units can cause erratic operation or false alarms. Regular inspection and tightening of terminal blocks is essential.

Diagnostics

Troubleshooting Guide

Control Unit Not Responding to ALCMS Commands
Likely Cause
Communication loss from cable damage, connector corrosion, or a network configuration error.
Diagnostic Steps
Check the communication link status/LEDs, test cable continuity, inspect connectors for corrosion, and verify the protocol/network configuration.
Corrective Action
Repair or replace the damaged cable/connector, correct the configuration, and activate redundant communication paths if fitted.
False Overcurrent/Undercurrent Fault Alarms
Likely Cause
Current sensor (transformer or shunt resistor) drift.
Diagnostic Steps
Compare the unit's current reading against a known-good reference ammeter and review the calibration history.
Corrective Action
Recalibrate the current sensing circuit against a reference ammeter, and replace the sensor if it cannot be brought within tolerance.
CCR Stuck on One Intensity Step
Likely Cause
Output relay contacts welded closed from high inrush current or frequent switching.
Diagnostic Steps
Inspect the relay contacts for welding or pitting, and review the switching frequency and inrush current history.
Corrective Action
Replace the welded relay with a correctly rated one, or upgrade to solid-state switching for heavy-duty applications.
Control Unit Loses Power or Resets Unexpectedly
Likely Cause
Internal power supply failure from capacitor ageing or voltage spikes.
Diagnostic Steps
Measure internal supply rail voltages, inspect capacitors for bulging or leakage, and check for a history of voltage spikes at the site.
Corrective Action
Replace the failed power supply module, and add UPS or surge protection upstream to prevent recurrence.
Configuration Settings Lost or Reverted
Likely Cause
Configuration corruption from a battery failure or EEPROM fault.
Diagnostic Steps
Check the backup battery/memory retention status and review whether a configuration backup exists.
Corrective Action
Replace the backup battery, restore configuration from backup, and re-verify all settings before returning to service.

Failure Modes & Root Causes

Communication Interface Failure
High Severity
Root Cause
Damaged or corroded communication cabling, a failed communication port, or electrical noise on a shared conduit run.
Effect
Control unit not responding to ALCMS commands, leaving the PAPI circuit unable to receive remote step or on/off commands.
Detection Method
Communication diagnostic/heartbeat check at the ALCMS, and continuity testing of the comms cable.
Current Sensing Calibration Drift
Medium Severity
Root Cause
Ageing of the current sensing component, or a reference voltage drifting away from its factory calibration over years of service.
Effect
False overcurrent/undercurrent fault alarms that do not correspond to an actual circuit condition.
Detection Method
Current sensing verification against a calibrated reference meter during scheduled maintenance.
Output Stage Contactor Sticking
High Severity
Root Cause
Contact wear or welding from repeated step-change cycling, or debris lodged in the contactor mechanism.
Effect
CCR stuck on one intensity step, unable to respond to a subsequent step-change command.
Detection Method
Functional step-change test across all levels, and physical inspection of the output stage contactor during maintenance.
Power Supply Instability
Medium Severity
Root Cause
A degraded internal power supply component, or an unstable incoming supply voltage outside the unit's rated tolerance.
Effect
Control unit loses power or resets unexpectedly, interrupting monitoring and control of the PAPI circuit.
Detection Method
Internal supply voltage monitoring, and correlation of reset events with logged incoming supply anomalies.
Configuration Memory Failure
Medium Severity
Root Cause
Backup battery depletion, or memory component ageing that fails to reliably retain settings through a power interruption.
Effect
Configuration settings lost or reverted to default after a power dip, requiring reprogramming before normal operation resumes.
Detection Method
Scheduled backup battery testing, and configuration verification after any power interruption event.
Precautions

Safety & Operational Notes

Isolate Before Internal Work
Electrical Safety

De-energise and lock out the unit's supply before opening the enclosure to access the output stage contactors, current sensing, or communication wiring, and verify zero energy before touching internal terminals.

Glide Path Safety Impact
Operational

The control unit governs the PAPI's intensity step and on/off state, which directly shapes the visual glide path indication pilots see on approach; any work that could affect step response requires airside coordination and, where the unit will be off-tolerance, a NOTAM.

Contactor Sticking / Arc Hazard
Electrical Safety

Do not manually operate the output stage contactors under load; debris or contact wear can leave them stuck on one step, and switching under load risks arcing given the circuit's constant-current characteristic.

Command-to-Output Verification
Verification

After any contactor, sensing, or communication work, verify commanded step against actual output across the full intensity range before returning the unit to automatic service, since a mismatch here directly changes what the pilot sees.

Confirm Manual Fallback Before Comms Work
Operational

Before servicing the communication interface, confirm the unit can still be controlled locally, since a communication fault removes ALCMS remote step and on/off commands until the link is restored.

PPE & Grounding
Personnel Safety

Use insulated tools and appropriate PPE when working on live circuits, and confirm the enclosure is bonded/grounded per the electrical design before closing it up.

FOD & Enclosure Integrity
Operational

Account for all tools and fasteners before closing the enclosure, and confirm the door/lid seal is properly reinstated to keep moisture and debris out of the control electronics.

Restore to Compliant State
Compliance

Do not leave the PAPI at an incorrect or unverified intensity step, or with communication to the ALCMS unrestored, after maintenance; confirm full-range step verification before closing out the work and cancelling any associated NOTAM.

Engineering & Expert Notes

Contactor Arc Damage Accumulates Before It Causes a Visible Fault
Electrical

Repeated switching under load, even within rated limits, gradually pits and roughens contactor contacts; a unit that has been in service for years can develop increasing contact resistance and heat at the contactor well before it produces a step failure a technician would notice on a routine check.

Confirm Local Control Actually Works, Not Just That It's Available
Operational

A unit can report local control as available in its status display while the local control path itself has a latent fault; physically exercise local control before relying on it as a fallback during communication interface work.

Full-Range Step Verification Catches Faults a Single-Step Check Misses
Verification

A contactor or sensing fault can affect only one or two intensity steps while others function correctly; verifying just the currently-commanded step after a repair can miss a fault that will only appear the next time ALCMS calls for a different step.

A Reported Step Mismatch May Be a Sensing Fault, Not a Contactor Fault
Troubleshooting

Current sensing feeding step-verification logic can itself drift or fail, causing the unit to report an incorrect step even when the actual output is correct; verify actual photometric output independently before replacing contactor hardware based on a reported mismatch alone.

Enclosure Seal Condition Affects Sensing Accuracy Over Time
Electrical

Moisture or dust ingress through a degraded door or lid seal can affect current-sensing and communication electronics gradually, producing intermittent step-verification or comms faults that look electronic in nature but originate from an enclosure sealing issue.

Log Comms Faults Separately From Step-Response Faults
Compliance

Because a communication fault and a step-response fault have different root causes and different urgency, one removes remote control while the other changes what the pilot sees, tracking them as distinct fault categories helps prioritise response and spot a pattern specific to one subsystem.

Quick Answers

Frequently Asked Questions

Short answers about PAPI control units: functions, fault detection, specifications, standards and maintenance.

Q1What is a PAPI control unit?

It is the electronic device that manages a PAPI system. It handles intensity selection, lamp or LED monitoring, fault detection and alarms, communication with the ALCMS and diagnostics. It is usually installed in the airfield electrical equipment room near the CCR, or integrated with the CCR itself.

Q2What does a PAPI control unit do?

It receives brightness commands from the ALCMS or a manual panel and converts them into current or PWM signals, monitors the electrical status of each PAPI unit, raises local and remote alarms on faults and logs the events, exchanges data with the ALCMS, and runs self-tests.

Q3Why does a PAPI need a control unit?

It makes four separately powered light units behave as one instrument. When ambient light changes, all four must step together, because if one lagged even briefly the red/white balance a pilot reads would be temporarily distorted for reasons unrelated to the aircraft's actual glide path.

Q4How does the control unit set intensity?

It takes a day, twilight or night brightness command and sends a control signal to the CCR to set the series current, for example 2.8 A, 3.4 A, 4.1 A, 5.2 A or 6.6 A. For LED systems it may send a PWM signal to the LED drivers instead.

Q5How does it detect faults?

It measures series-circuit current using a current transformer or shunt and compares it with the target. Advanced units monitor each PAPI unit individually, often with a multiplexed measurement system. It flags lamp failure, open circuit, short circuit, over-current and under-current, sounds a local alarm and sends a fault message to the ALCMS.

Q6What happens if the ALCMS fails?

The unit often has a manual override switch or keypad so intensity can be set locally. Before servicing the communication interface, confirm local control still works, because a communication fault could otherwise leave the PAPI at an unintended step.

Q7What are typical PAPI control unit specifications?

Input is 115/230 VAC or 24/48 VDC (portable), using 50 to 150 W. It monitors 4 PAPI units as standard (more with expansion), uses 3 or 5 brightness steps, and communicates over Modbus RTU, Modbus TCP, BACnet or Profibus. It has an LCD, Form C alarm relays and a fault log of up to 1,000 timestamped events, in IP20 (indoor) or optional IP65.

Q8Which standards apply to PAPI control units?

The main references are ICAO Annex 14 (PAPI control and monitoring), FAA AC 150/5345-28, FAA AC 150/5345-56 (L-890 ALCMS), and IEC 61000-6-2 and IEC 61000-6-4 for EMC immunity and emissions. Always verify the current edition.

Q9How often should a PAPI control unit be maintained?

Typical practice is a semi-annual communication link test, and annual checks of current sensor calibration, relay contacts, power supply and a configuration backup and verification. Your airport's approved maintenance programme takes precedence.

Q10What are the common PAPI control unit problems?

Communication loss from cable damage, connector corrosion or network configuration errors, current sensor drift causing false alarms, relay contacts welding from inrush current, internal power supply failure from capacitor ageing, configuration corruption from battery or EEPROM failure, and loose or corroded wiring.
