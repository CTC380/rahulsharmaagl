ALCMS & Control System Maintenance

The dedicated maintenance framework for the Airfield Lighting Control and Monitoring System (ALCMS) and its associated control, monitoring, communication and interface equipment. Division 17 maintains the complete control chain — from the operator's command, through the PLC, interface and CCR, out to the field, and back through feedback, alarm and event recording.

Objective: confirming that the ALCMS screen is operational is not sufficient. The complete chain of command, execution, feedback, alarm and event recording must be verified on every applicable task in this division.

Core rule: a control command is not considered verified until command, equipment response, feedback and event/alarm behaviour have all been confirmed.

ALCMS Fault-Trace Method

When an ALCMS command does not produce the expected response, the fault is traced through the same eight-point chain regardless of which topic in this division is being worked.

1
Operator / HMI

Is the command being generated?

2
Communication

Is the command leaving the HMI/ALCMS?

3
PLC

Is the PLC receiving/processing the command?

4
Interface

Is the interface transmitting the command?

5
CCR

Is the CCR in remote mode and receiving the command?

6
Field System

Is the AGL equipment responding?

7
Feedback

Is the actual condition returning to the ALCMS?

8
Display

Is the HMI displaying the correct condition?

Pre-Maintenance Requirements

Before any Division 17 task begins, four requirement groups must be closed out.

Work Planning

  • Identify system/asset — ALCMS ID, workstation, PLC, network element
  • Review previous maintenance history, alarms, and defects
  • Confirm task, tools, spares, and approved test methods
  • Confirm authorized personnel for any PLC/configuration change

Operational Coordination

  • Obtain required work authorization
  • Coordinate with ATC / airport operations before any live command test
  • Confirm alarm test method will not create an unintended operational condition
  • Establish communication arrangements with the control room

Safety & Access

  • Identify electrical and control-system hazards
  • Apply isolation / LOTO requirements where required
  • Follow approved cybersecurity and access-control procedures
  • Verify user access changes are authorized before applying them

Documentation

  • Date, work-order number, technician, supervisor
  • System/workstation/PLC identification
  • Initial condition and any active alarms
  • Configuration/backup reference in use

Core Principle

The strongest principle for Division 17 governs every one of its 39 topics, whether preventive, corrective, or functional.

Do not verify only the screen — verify the complete control loop. Operator → HMI → ALCMS → PLC/Control Logic → Interface → CCR → AGL Field System → Feedback → Alarm/Event Log → HMI Status. This makes Division 17 the control, monitoring and information-integrity backbone of the AGL Maintenance Handbook.

Frequently Asked Questions

Quick answers about alcms & control system maintenance, based on the topics in this division.

8 QUESTIONS
Q1What is ALCMS and control system maintenance?

It is the dedicated framework for the Airfield Lighting Control and Monitoring System and its associated control, monitoring, communication and interface equipment.

Q2What does Division 17 of the AGL Maintenance Handbook cover?

Division 17 (ALCMS & Control System Maintenance) contains 39 topics in three groups: Group A Preventive Maintenance (20 topics), Group B Corrective Maintenance (11 topics) and Group C Functional Maintenance (8 topics).

Q3Is it enough to confirm that the ALCMS screen is operational?

No. The complete chain of command, execution, feedback, alarm and event recording must be verified. A control command is not considered verified until the command, equipment response, feedback and event or alarm behaviour have all been confirmed.

Q4What five core functions are verified?

Control (can the operator issue the command), Execution (does it reach the intended equipment), Feedback (does ALCMS correctly indicate equipment status), Alarm (does the system identify abnormal conditions) and Record (does it correctly record the event and system response).

Q5What is the control-chain architecture?

Operator/HMI, ALCMS, PLC/control logic, interface, CCR, AGL series circuit, field equipment, then feedback returning to ALCMS. Every task is judged against this end-to-end chain, not the HMI screen alone.

Q6How do you trace an ALCMS fault?

When a command does not produce the expected response, trace an eight-point chain: is the command generated at the HMI, leaving the HMI/ALCMS, received and processed by the PLC, transmitted by the interface, received by a CCR in remote mode, and acted on by the field system, and is the actual condition then returned as feedback and shown correctly on the display.

Q7What must be closed out before ALCMS maintenance begins?

Four requirement groups. Work planning covers identifying the system, reviewing history and alarms, and confirming authorized personnel for any PLC or configuration change. Operational coordination covers work authorization and coordinating with ATC or airport operations before any live command test. Safety and access covers isolation or LOTO where required and approved cybersecurity and access-control procedures. Documentation covers the work order, system identification, initial condition and the backup or configuration reference in use.

Q8How are ALCMS conditions classified?

Good (fully functional and stable, routine PM), Acceptable (minor non-critical deterioration, monitor), Deteriorating (developing hardware, software or communication issue, planned maintenance), Defective (control or monitoring function compromised, corrective maintenance) and Critical (loss of an essential control or monitoring function).
